================================================================================
                    [Git & GitHub 완벽 사용 가이드]
================================================================================

본 문서는 Git을 처음 사용하거나 원격 저장소(GitHub)와 연동할 때 필요한
기본 설정부터 코드 업로드(Push), 다운로드(Pull), 동기화 및 트러블슈팅까지
핵심 과정을 정리한 가이드입니다.

--------------------------------------------------------------------------------
1. Git 최초 사용자 정보 설정 (최초 1회 실행)
--------------------------------------------------------------------------------
Git을 PC에 설치한 후 커밋 작성자를 식별하기 위해 사용자 이름과 이메일을 등록합니다.

  # 사용자 이름 등록
  git config --global user.name "사용자이름"

  # GitHub 계정에 등록된 이메일 주소 등록
  git config --global user.email "사용자이메일@example.com"

  # 등록된 설정 확인
  git config --list


--------------------------------------------------------------------------------
2. GitHub 로그인 및 인증 연동
--------------------------------------------------------------------------------
Windows 환경에서는 Git 설치 시 기본 포함된 'Git Credential Manager(GCM)'를 통해
브라우저로 간편하게 인증합니다.

  1) 최초 'git push' 실행 시 브라우저 또는 팝업 창이 표시됩니다.
  2) "Sign in with your browser" 버튼을 클릭합니다.
  3) 브라우저에서 GitHub 로그인 후 "Authorize GitCredentialManager" 승인 버튼을 누릅니다.
  4) 한 번 인증하면 Windows 자격 증명 관리자에 저장되어 이후 비밀번호 입력 없이 동작합니다.

  ※ 만약 팝업이 뜨지 않거나 인증 오류가 발생하는 경우:
     - GitHub 웹사이트 > Settings > Developer settings > Personal access tokens (classic)
     - 'repo' 권한을 체크한 토큰(PAT)을 생성하여 비밀번호 자리에 토큰을 입력합니다.


--------------------------------------------------------------------------------
3. 보안을 위한 제외 파일 설정 (.gitignore)
--------------------------------------------------------------------------------
API 키(.env), 가상환경(venv), 데이터베이스(chroma_db) 등 민감하거나 불필요한 파일이
GitHub에 공개되지 않도록 프로젝트 루트 폴더에 '.gitignore' 파일을 생성합니다.

  [주요 제외 항목 예시]
  .env               # API 키 및 비밀 환경변수
  venv/              # 파이썬 가상환경
  __pycache__/       # 파이썬 바이트코드 캐시
  chroma_db/         # 로컬 벡터 DB 데이터
  *.sqlite3          # 로컬 DB 파일


--------------------------------------------------------------------------------
4. 저장소 시작하기 (상황별 2가지 방법)
--------------------------------------------------------------------------------

[방법 A] 이미 내 컴퓨터에 작성된 폴더를 새로 깃에 올릴 때
  cd C:\workspaces\kein_edu

  # 1) Git 로컬 저장소 초기화 (.git 폴더 생성)
  git init

  # 2) 파일 상태 확인 (빨간색: 변경되거나 추가된 파일)
  git status

  # 3) 전체 파일 장바구니(스테이징)에 담기
  git add .

  # 4) 버전 기록(커밋) 남기기
  git commit -m "Initial commit: 첫 번째 커밋 메시지"

  # 5) 기본 브랜치 이름을 main으로 변경
  git branch -M main

  # 6) GitHub 원격 저장소와 로컬 저장소 연결
  git remote add origin https://github.com/계정명/저장소이름.git

  # 7) GitHub로 첫 업로드 (원격 main 브랜치 지정)
  git push -u origin main


[방법 B] GitHub에 이미 존재하는 저장소를 내 컴퓨터로 통째로 가져올 때
  cd C:\workspaces

  # 원격 저장소를 복제(Clone)하여 새 폴더 생성
  git clone https://github.com/계정명/저장소이름.git

  # 복제된 폴더로 이동
  cd 저장소이름


--------------------------------------------------------------------------------
5. 일상적인 작업 흐름: 변경사항 올리기 (Add -> Commit -> Push)
--------------------------------------------------------------------------------
코드를 수정하거나 새로운 파일을 만든 후 GitHub에 반영할 때 반복하는 과정입니다.

  # 1) 변경된 파일 확인
  git status

  # 2) 수정한 파일 스테이징
  git add .                # 모든 변경사항 추가
  # 또는
  git add 파일명.py        # 특정 파일만 추가

  # 3) 커밋 메시지 작성
  git commit -m "feat: 검색 기능 개선 및 버그 수정"

  # 4) GitHub 원격 저장소로 업로드
  git push


--------------------------------------------------------------------------------
6. 원격 변경사항 내 컴퓨터로 내려받기 (Pull & Fetch)
--------------------------------------------------------------------------------
GitHub 웹에서 직접 수정했거나 다른 PC에서 올린 내용을 현재 컴퓨터로 동기화할 때 사용합니다.

  # 원격의 최신 커밋을 내려받아 현재 로컬 코드에 즉시 병합(추천)
  git pull origin main

  # 원격 변경사항을 확인만 하고 바로 병합하지는 않을 때
  git fetch origin

  # [참고] 로컬과 원격이 서로 다른 히스토리를 가지고 있어 pull이 거부될 때
  git pull origin main --allow-unrelated-histories


--------------------------------------------------------------------------------
7. 원격 저장소(Remote) 주소 관리
--------------------------------------------------------------------------------

  # 현재 연결된 원격 저장소 확인
  git remote -v

  # 원격 저장소 주소 변경 (저장소 이름을 바꿨거나 URL이 변경된 경우)
  git remote set-url origin https://github.com/계정명/새로운저장소.git

  # 기존 연결 삭제
  git remote remove origin


--------------------------------------------------------------------------------
8. 유용한 확인 및 되돌리기 명령어
--------------------------------------------------------------------------------

  # 커밋 히스토리 한 줄로 간략히 확인
  git log --oneline -n 10

  # 직전 커밋과 현재 수정한 코드 간의 차이 비교
  git diff

  # 수정한 파일을 마지막 커밋 상태로 되돌리기 (수정사항 취소)
  git restore 파일명.py

  # git add 취소하기 (스테이징 해제)
  git restore --staged 파일명.py

  # 최근 커밋 취소하기 (파일 수정사항은 유지한 채 커밋만 취소)
  git reset --soft HEAD~1
