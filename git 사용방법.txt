                    [Git & GitHub 완벽 사용 가이드]
================================================================================

본 문서는 Git 설치부터 환경 설정, GitHub 연동, 일상적인 코드 업로드/다운로드,
그리고 실제 작업 중 자주 겪는 경고(LF/CRLF) 및 트러블슈팅 과정을
현재 계정(chiyanude-blip)과 실제 저장소 주소를 기준으로 정리한 가이드입니다.

--------------------------------------------------------------------------------
1. Windows 터미널에서 Git 설치하기
--------------------------------------------------------------------------------
Windows PowerShell(또는 명령 프롬프트)에서 기본 패키지 관리자인 'winget'을 사용해
브라우저 다운로드 없이 바로 Git을 설치할 수 있습니다.

  # 1) Windows 패키지 관리자로 Git 최신 버전 자동 설치
  winget install --id Git.Git -e --source winget

  # 2) 설치 완료 후 터미널 창을 껐다 킨 뒤 설치 확인
  git --version


--------------------------------------------------------------------------------
2. Git 사용자 정보 설정 (현재 계정 기준)
--------------------------------------------------------------------------------
커밋 작성자 정보를 현재 GitHub 계정과 동일하게 전역(Global)으로 설정합니다.

  # 사용자 이름 등록
  git config --global user.name "chiyanude-blip"

  # GitHub 등록 이메일 주소 등록
  git config --global user.email "chi.yanude@gmail.com"

  # 한글 파일명이 '\354\202...' 숫자/이스케이프 코드로 깨질 때 한글 그대로 표시
  git config --global core.quotepath false

  # 등록된 설정 확인
  git config --list

  # 사용자 이름, 사용자 이메일 확인
  git config --global user.name
  git config --global user.email

--------------------------------------------------------------------------------
3. GitHub 브라우저 로그인 및 자격 증명 연동
--------------------------------------------------------------------------------
Windows 환경에서는 Git 설치 시 기본 포함된 'Git Credential Manager(GCM)'를 통해
브라우저로 간편하게 1회 로그인합니다.

  1) 최초 'git push' 실행 시 브라우저 또는 로그인 팝업 창이 뜹니다.
  2) "Sign in with your browser" 버튼을 클릭합니다.
  3) 브라우저에서 로그인 후 "Authorize GitCredentialManager" 승인 버튼을 누릅니다.
  4) 인증이 완료되면 Windows 자격 증명 관리자에 영구 저장되어 이후 비밀번호 없이 동작합니다.

  ※ 만약 팝업이 뜨지 않거나 권한 오류가 발생할 경우:
     - GitHub 웹사이트 > Settings > Developer settings > Personal access tokens (classic)
     - 'repo' 권한을 체크한 토큰(PAT)을 발급받아 비밀번호 자리에 토큰을 입력합니다.

4. 보안을 위한 제외 파일 설정 (.gitignore)
--------------------------------------------------------------------------------
API 키(.env), 가상환경(venv), 데이터베이스(chroma_db) 등 민감하거나 불필요한 파일이
GitHub에 공개되지 않도록 프로젝트 루트 폴더에 '.gitignore' 파일을 생성합니다.

  [주요 제외 항목]
  .env               # API 키 및 환경변수
  venv/              # 파이썬 가상환경
  __pycache__/       # 파이썬 바이트코드 캐시
  chroma_db/         # 로컬 벡터 DB 데이터
  *.sqlite3          # 로컬 DB 파일


--------------------------------------------------------------------------------
5. 최초 저장소 시작 및 GitHub 원격 저장소 연결 (1회 진행)
--------------------------------------------------------------------------------
현재 로컬 폴더(C:\workspaces\kein_edu)를 Git 저장소로 초기화하고
GitHub 원격 저장소(https://github.com/chiyanude-blip/test.git)에 연결한 과정입니다.

  cd C:\workspaces\kein_edu

  # 1) Git 로컬 저장소 초기화 (.git 폴더 생성)
  git init

  # 2) 파일 전체 스테이징
  git add .

  # 3) 첫 커밋 생성
  git commit -m "Initial commit"

  # 4) 기본 브랜치 이름을 main으로 지정
  git branch -M main

  # 5) GitHub 원격 저장소 연결
  git remote add origin https://github.com/chiyanude-blip/test.git

  # 6) GitHub로 첫 업로드 (upstream 설정)
  git push -u origin main

6. 일상적인 코드 수정 후 업로드 과정 (Add -> Commit -> Push 3단계)
--------------------------------------------------------------------------------
파일을 수정한 뒤 GitHub에 반영할 때는 반드시 아래 3단계를 거쳐야 합니다.

  [1단계: 파일 상태 확인 및 장바구니 담기]
  git status
  git add .
  
  ※ 중요: git add 경고(Warning) 안내
  ----------------------------------------------------------------------------
  "warning: in the working copy of '...', LF will be replaced by CRLF ..."
  -> 에러가 아니며 단순 줄바꿈 알림입니다!
     Windows 줄바꿈(CRLF)과 Linux/Git 줄바꿈(LF) 차이를 Git이 자동으로 
     변환해 주겠다는 정상적인 안내이므로 무시하고 다음 단계로 진행하시면 됩니다.
  ----------------------------------------------------------------------------

  [2단계: 버전 확정(커밋)]
  'git add .'만 실행한 상태에서는 아직 내 컴퓨터의 임시 보관함에만 담긴 것이며,
  커밋을 해야 하나의 버전으로 묶여 기록됩니다.
  
  git commit -m "주석 수정 및 기능 개선"

  [3단계: GitHub로 실제 업로드]
  최종적으로 원격 저장소로 밀어올립니다.
  
  git push

7. 어떤 파일이 수정되었는지 확인하는 방법 (Status & Diff)
--------------------------------------------------------------------------------
작업 중 어떤 파일이 변경되었는지, 파일 안에서 구체적으로 어떤 글자/코드가
바뀌었는지 확인할 때 사용하는 명령어입니다.

  [1] 수정된 파일 목록 및 상태 확인 (git status)
  ----------------------------------------------------------------------------
  git status

  터미널에 출력되는 색상과 메시지로 파일 상태를 파악할 수 있습니다:
  - 빨간색 (Changes not staged for commit):
      기존 파일이 수정되었으나 아직 'git add'하지 않은 파일
  - 빨간색 (Untracked files):
      새로 생성되었으나 아직 Git이 추적하지 않는 새 파일
  - 초록색 (Changes to be committed):
      'git add'가 완료되어 커밋 대기 중인 파일

  # 간략하게 한 줄씩 요약해서 보고 싶을 때 (추천)
  git status -s
    M  파일명.py  (초록색 M: 스테이징 완료된 수정 파일)
     M 파일명.py  (빨간색 M: 스테이징 안 된 수정 파일)
    ?? 새파일.py  (빨간색 ??: 새로 추가된 파일)


  [2] 파일 안에서 구체적인 변경 내용(코드 줄) 비교 (git diff)
  ----------------------------------------------------------------------------
  # 1) 아직 'git add'하지 않은 수정 내용 전체 비교
  git diff

  # 2) 특정 파일의 수정 내용만 콕 집어서 비교
  git diff part04/02_perplexity_streamlit.py

  # 3) 'git add'를 한 후, 커밋하기 직전에 담긴 내용 확인
  git diff --staged
  # (또는 git diff --cached)

  # 4) add 여부와 상관없이 마지막 커밋 이후 바뀐 모든 내용 비교
  git diff HEAD

  ※ diff 화면 읽는 법:
     - 빨간색 (- 로 시작하는 줄): 삭제되거나 수정 전 기존 코드
     + 초록색 (+ 로 시작하는 줄): 새롭게 추가되거나 수정한 최신 코드


  [3] 최근 커밋에서 어떤 파일들이 수정되었는지 확인
  ----------------------------------------------------------------------------
  # 최근 커밋별 수정된 파일 목록과 변경 줄 수 통계 보기
  git log --stat -n 3

  # 직전 커밋(가장 최근 커밋)의 구체적인 변경 내용 보기
  git show

8. 원격 저장소 변경사항 내 컴퓨터로 내려받기 (Pull & Fetch)
--------------------------------------------------------------------------------
GitHub 웹사이트에서 직접 코드를 수정했거나, 다른 컴퓨터에서 올린 내용을 가져올 때:

  # 원격의 최신 커밋을 내려받아 현재 로컬 코드에 즉시 합치기 (가장 흔히 사용)
  git pull origin main

  # 원격 변경사항을 확인만 하고 바로 합치지 않을 때
  git fetch origin

  # [참고] 로컬과 원격의 히스토리가 달라 충돌/거부될 때 강제 병합 허용
  git pull origin main --allow-unrelated-histories


--------------------------------------------------------------------------------
9. 원격 저장소(Remote) 주소 관리
--------------------------------------------------------------------------------

  # 현재 연결된 원격 주소 확인
  git remote -v

  # 원격 저장소 주소 변경 (저장소 이름이 변경된 경우)
  git remote set-url origin https://github.com/chiyanude-blip/<새저장소이름>.git

  # 원격 연결 삭제
  git remote remove origin


--------------------------------------------------------------------------------
10. 유용한 확인 및 되돌리기 명령어
--------------------------------------------------------------------------------

  # 커밋 기록을 한 줄로 깔끔하게 보기
  git log --oneline -n 10

  # 직전 커밋과 현재 수정된 파일 내용 비교
  git diff

  # 수정한 파일을 마지막 커밋 상태로 되돌리기 (수정사항 취소)
  git restore 파일명.py

  # git add 취소하기 (스테이징 해제)
  git restore --staged 파일명.py

  # 최근 커밋 취소하기 (작업한 코드는 유지한 채 커밋 기록만 취소)
  git reset --soft HEAD~1
